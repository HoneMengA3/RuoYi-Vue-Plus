# 汇流（ESIP）一期设计基线（立项版 v1）

> 文档属性：一期范围与详细设计输入，不含营销话术及合同条款。  
> 决策状态：已合并 Boss 最终判决 **B / A / B / C**。  
> 一期目标：在强监管网络环境下，完成“资产登记—申请审批—授权生效/到期回收—跨网交换—全链路审计—版本发布/回滚”的最小闭环。

---

## 1. 一期范围与边界

### 1.1 标准交付范围

1. 资产目录与五类能力分权：发现、申请、调用、查看全量、再分发。
2. 单级业务审批；高密级资产可追加安全复核。
3. 以应用为授权主体的授权、到期自动回收和通知。
4. 跨网文件交换：断点续传、幂等去重、完整性校验、限额与错误码。
5. 只读 API 薄代理：原协议透传、鉴权、策略校验、流控、超时与审计；不做完整 RPC 中转。
6. 全链路审计与审计导出。
7. 制品版本化发布、灰度生效与回滚。
8. SDK、示例、自测工具及“自测通过证明”导出。

### 1.2 一期明确不做

不做用户脚本/Python 沙箱、共享调度集群、依赖触发作业、完整 RPC 同步中转、直连源库 Extract、数据湖/报表/血缘自研、图形编排，以及由 AI 参与审批、权限决策或生产作业变更。

调度仅保留实例模型壳：实例键、完整状态枚举、触发源枚举全部入库；一期只实现手动和定时触发。演示若需作业，仅使用平台内置受控作业，不进入一期 license、卖点或加价项。

---

## 2. 部署单元与耦合原则

一期划分为 7 个独立部署单元：

| 部署单元 | 职责边界 |
|---|---|
| `control` | 身份、授权与服务端策略决策（PDP） |
| `catalog` | 资产目录、资产分级与契约元数据 |
| `workflow` | 申请、审批、授权生效与回收流程 |
| `exchange` | 文件交换与只读 API 薄代理；唯一允许接触业务字节的模块 |
| `audit` | 审计事件接收、校验、存储与导出 |
| `release` | 制品版本、发布、灰度和回滚 |
| `sdk+selfcheck` | SDK、示例、自测工具及通过证明 |

强制架构约束：

- 模块之间只通过事件与版本化元数据契约耦合，不共享库表。
- 控制面、执行面和数据面分离。
- `exchange` 可独立扩缩容、升级和回滚。
- 其余模块故障不得破坏已进入传输阶段的数据完整性；是否继续交付按已缓存且未过期的授权决策执行。
- 服务端策略校验是唯一权威，客户端校验仅改善体验，不能成为授权依据。

---

## 3. 纯通道数据面定义

一期默认且强制为纯通道模式：

1. 平台不持久化业务数据副本；中转桶仅执行“接收—暂存—交付—到期删除”。
2. 中转桶不是资产库，不支持检索、浏览、列举、二次消费、内容解析或派生加工。
3. 到期按资产策略删除，平台不提供恢复；默认 TTL 为 7 天，配置上限暂定 30 天，具体值作为部署参数而非代码常量。
4. 删除前支持 T-2、T-1 告警；服务保障只覆盖有效交付窗口内的平台故障。
5. `sink` 扩展点一期只定义接口契约，不提供实现，默认关闭，管理面不暴露开启入口。
6. 后续即使启用 `sink`，也必须复用同一授权与审批路径，不允许旁路写入。
7. 为三期落湖预留但不落业务数据：审计事件保留完整交换血缘要素、`content_hash`、`exchange_instance_id` 和可选 `schema` 声明位。

## 4. 元数据、实例与审计契约

### 4.1 强制审计字段

以下字段从第一天起强制，缺失视为审计事件写入失败：

- 事件：`event_id`、`event_time`、`event_type`
- 资产：`asset_id`、`asset_type`
- 主体：`source_app`、`target_app`、`actor`
- 行为：`action`、`result`、`error_code`
- 策略：`policy_id`、`decision_ttl`
- 制品：`artifact_version`、`business_date`
- 交换：`exchange_instance_id`、`content_hash`、`bytes`、可选 `rows`

`event_id` 全局唯一；`exchange_instance_id` 贯穿接收、分片、续传、校验、交付与删除事件。文件完整性以内容哈希为最终依据，幂等键用于防止重复入账。

### 4.2 actor 规则（Boss 判决 A）

- 默认权威主体是应用：由接入通道绑定的 `source_ip + client_certificate + app_id` 确认。
- 自然人身份通过标准可选请求头透传，不要求 B 类系统为此修改核心代码。
- 资产元数据增加 `human_actor_required`；高密级资产可将其设为 `true`。
- PDP 在策略决策前校验该头：非强制资产缺失时允许按应用主体决策并记录 `actor=app:{app_id}`；强制资产缺失、格式非法或无法映射时直接拒绝，并生成拒绝审计事件。
- 客户端传来的自然人信息不是单独信任源，必须与已认证通道和应用身份共同入审计。

### 4.3 作业实例模型壳

作业实例键固定为：`business_date + job_id + artifact_version`。完整状态与触发源枚举均落库，一期仅实现手动、定时触发和其对应状态流转，其他枚举保留但不可执行。

## 5. 薄代理鉴权与分级降级

### 5.1 鉴权透传双通道

1. **原系统通道**：默认原样透传业务系统已有凭据，不改变接口语义、参数或报文。
2. **汇流通道**：使用 `source_ip + client_certificate + app_id` 绑定调用应用；汇流新签名仅作为可选增强，不作为一期接入前提。

### 5.2 分级兜底

- **L1 策略面**：PDP 正常时实时决策；短暂不可用时仅使用尚未过期的缓存决策，严格遵守 `decision_ttl`，不得扩大权限。
- **L2 审计面（Boss 判决 B）**：审计先写本地加密 WAL，再异步补写。WAL 达阈值或不可持久化时按资产密级分叉：
  - 低密级且只读：允许 fail-open，但必须生成异常标识、强告警并在恢复后补写；是否允许由部署策略显式配置。
  - 中高密级：fail-closed，拒绝新请求。
  - 写操作不适用低密级只读放行规则。
- **L3 代理实例**：无状态多实例部署，通过健康检查和 VIP 摘除故障实例，不把请求自动绕回源系统直连。
- **L4 集群级**：平台不得自动直通或静默关闭审计，只能进入 break-glass 流程。

### 5.3 break-glass（Boss 判决 C）

- 保留能力，但代码配置与部署模板均默认关闭，且不出现在普通管理界面。
- 启用必须由客户显式配置，完成风险确认，并由双人审批或等价客户控制措施授权。
- 每次启用必须设置适用资产/应用范围和到期时间，强告警、全程留痕，到期自动关闭。
- 应急期间至少记录本地防篡改事件；恢复后必须补录集中审计并完成复盘。
- break-glass 不是自动 fail-open、不是一期卖点，也不计入标准 license 能力承诺。

---

## 6. 私有协议适配器交付边界（Boss 判决 B）

- 私有协议适配器不属于一期平台标准交付项。
- 标准交付仅包含 SDK、示例、自测工具、接入契约和协议适配器 SPI。
- SPI 一期只冻结签名、生命周期、错误码、幂等和审计回调契约，不提供私有协议实现。
- 具体适配器由实施团队或客户按 SDK 自研，并独立估算和验收；不得修改平台核心代码。
- 无文档私有二进制协议不进入一期准入承诺。

## 7. 工具链依赖与实施顺序

为保证接入人天可兑现，排期顺序固定如下：

1. **契约先行**：冻结元数据、审计事件、错误码、幂等键、SPI 和 SDK 接口。
2. **同批交付**：`exchange` 最小链路与 SDK、示例、自测工具同时开发，禁止先交服务端再补工具。
3. **自测闸门**：自测覆盖连通性、证书、鉴权、限额、幂等重复提交、断点续传、完整性校验、流控、超时和审计可查，并可导出“自测通过证明”。目标是接入方自助定位不少于 80% 的问题。
4. **PoC 串行准入**：跨网交换通过后，才进入授权审计闭环；再通过后，才进入发布回滚验证。
5. **人天承诺闸门**：SDK、示例、自测工具缺任一项，不得承诺标准接入人天；估算按翻倍处理。

校准后的人天口径：

- 文件交换 Agent/挂载目录模式：2–3 人天。
- 文件交换 SDK 模式：4–6 人天。
- 只读 API 薄代理：2–3 人天，前提是原鉴权可透传。
- 首个网段网络放行：另加 3–5 人天；后续同类网段另加 1–2 人天。增加项属于网络放行流程，不计为业务系统核心改造。

## 8. PoC 准入（2–3 周，严格串行）

### PoC #1：真实网络管制下跨网文件交换

必须验证接入节点穿透、大文件断点续传、重复/乱序通知幂等、完整性校验和断网重连；结果要求零重传错误、零重复入账。未通过则不进入开发排期。

### PoC #2：授权策略与审计闭环

服务端可复现申请、审批、授权生效、到期回收、越权拒绝和审计查询/导出；高密级自然人头强制规则可验证；审计导出件须能作为安全取证材料接受评审。

### PoC #3：版本发布与回滚

完成一次真实制品变更，5 分钟内生效，1 分钟内回滚；发布、灰度、验证、回滚全程留有可关联审计事件。

PoC 期间同步会签两项外部依赖：客户网络管制开放节奏、安全部门国密/等保口径。

---

## 9. 一期验收与二期闸门

以下四条缺一不开二期：

1. **接入人天可控**：以 2 个 A 类系统和 1 个 B 类系统为样本；标准能力就绪前提下，每系统不超过 5 人天，三系统合计目标 5–10 人天。特殊 SDK 路径与首网段网络放行单列，不混入标准改造量。
2. **权限可回收、可审计**：管理员不编辑策略表达式；授权 10 分钟内生效，到期自动回收并通知，越权请求由服务端拒绝且可导出完整证据链。
3. **跨网文件交换可演示**：在真实网络管制下完成断点续传、幂等和完整性验证。
4. **变更可发布、可回滚**：5 分钟内生效、1 分钟内回滚，全程可审计。

体验底线：填单不超过 15 分钟且至少 70% 字段预填；普通资产采用单级业务负责人审批，目标 1 个工作日内完成，高密级资产才追加安全复核。

---

## 10. 一期准入排除

一期不承诺：纯人工遗留系统、无文档私有二进制协议系统、低于 1 秒的实时链路、物理隔离涉密网段。上述场景分别进入人工兜底、专项适配评估、后续低延迟方案或专用摆渡方案，不得通过实施口头承诺并入一期标准范围。
