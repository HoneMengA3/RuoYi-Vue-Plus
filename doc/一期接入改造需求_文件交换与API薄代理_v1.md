# 一期接入路径需求（应用接入方口径，供研发部详细设计输入）

> 范围：只含一期两条接入路径——文件交换、只读 API 薄代理。
> 不涉及营销话术与合同条款。验收口径与 Boss 一期验收四条对齐（人天可控、权限可回收可审计、跨网可演示、可发布可回滚）。

---

## 1. 标准文件交换路径（FILE-EX-01）

### 1.1 最小改造面（只允许发生在适配层）
- 源系统按契约将增量文件推送至接入节点/中转桶（支持 SDK 落盘或挂载目录两种方式）。
- 下游从指定位置拉取，平台侧负责断点续传、校验、幂等去重。
- 已有标准 REST/文件导出能力的系统：适配层注册 + 资产登记 + 联调。估算 2–5 人天。
- 老系统（仅库表/私有协议）：适配器开发 + 数据核对。估算 15–25 人天。
- 新系统（开发期即规划接入）：SDK 接入 + 自测。估算 3–5 人天。
- 前提：平台提供 SDK、示例、自动接入自测工具；缺任一项人天翻倍。

### 1.2 绝对不能要求业务系统做的事（红线）
- 不给汇流开源库直读权限（不做直连 Extract）。
- 不内嵌 Agent/不改核心代码，改造只允许在接口适配层。
- 不要求业务系统自带幂等/重试/断点续传（平台侧标准能力）。
- 不要求按汇流字段字典重排数据（格式转换由平台/适配器做）。
- 不拿生产环境当联调环境（测试网段/沙箱，联调数据可造可清）。

### 1.3 对 SDK 与自测工具的接口期望（前置依赖）
- SDK 覆盖：鉴权、上传/下载、断点续传、幂等键、错误码规范。
- 自测工具覆盖：连通性、证书、限额、重复提交、超时重试；接入方自测可定位 ≥80% 问题。
- 自测工具必须能导出「自测通过证明」，作为接入验收证据。

### 1.4 验收口径
- 一个典型系统从立项到联调通过 ≤ 5 人天（有标准接口前提）。
- 断点续传、幂等、校验在自测工具内可一键验证。
- 跨网段交换在客户真实网络管制下可演示（对应 PoC #1）。

## 2. 只读 API 薄代理路径（API-PX-01）

### 2.1 最小改造面
- 现有接口原样注册到目录，仅挂到代理后面，不改业务逻辑、不改协议。
- 代理只做：鉴权、审计、流控、超时处理；不做协议转换、不做编排、不落数据。
- 按现有接口登记资产即可接入，改造面 ≈ 注册 + 联调（按第 1 节人天口径的同级或更低）。

### 2.2 绝对不能要求业务系统做的事（红线）
- 不要求接口改造成汇流协议/参数格式（仅原样透传）。
- 不要求为汇流增加额外幂等/补偿逻辑（流控与超时由代理声明并兜底）。
- 不要求业务系统参与汇流的鉴权实现（代理侧完成，业务侧保持现状）。

### 2.3 对 SDK 与自测工具的接口期望
- 注册/联调向导：上传接口定义（OpenAPI/描述文件）→ 自动生成测试用例。
- 自测工具覆盖：连通性、证书、鉴权头、流控触发（限流生效可观测）、超时行为、审计事件可查。
- 强制声明字段：超时、QPS、熔断（一期只声明和校验，不实现转发增强）。

### 2.4 验收口径
- 一个现有 REST 接口从注册到自测通过 ≤ 1 人天。
- 限流与超时行为能在自测中触发并留下审计事件。
- 代理不可用时业务接口行为不劣化（平台故障不影响源系统直连可用性——薄代理失败需快速降级/放行策略明确）。

## 3. 一期不承诺接入的准入排除清单（售前/交付据此卡边界）

| 场景 | 排除原因 | 处理 |
|---|---|---|
| 纯人工操作的遗留系统（无程序接口） | 只能半自动 | 一期不承诺自动交换，人工兜底 |
| 无文档的私有二进制厂商系统 | 需厂商配合或逆向，风险不可控 | 一期排除，不进准入承诺 |
| <1s 实时性要求的低延迟链路 | 中转架构不适用 | 一期排除，留二期独立集群或点对点例外 |
| 物理隔离的涉密网段 | 跨网通道过不去 | 需专用摆渡方案，非一期范围 |

---

## 4. 研发部必须接住的接口承诺（决定人天能否兑现）

1. SDK + 自测工具是**第一依赖项**，模块拆分中优先级最高。
2. 自测工具可导出「通过证明」，作为接入验收和审计证据链的一部分。
3. 人天预估（2–5 / 15–25 / 3–5）以上述工具就绪为前提；工具未就绪不得对外承诺人天。
